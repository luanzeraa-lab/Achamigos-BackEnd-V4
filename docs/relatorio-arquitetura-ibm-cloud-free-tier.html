Uma rota IBM para colocar a API no ar.

Proposta de arquitetura do backend Achamigos usando a conta gratuita da IBM Cloud, créditos iniciais e uma evolução possível para VPC quando a aplicação precisar de mais controle.

Premissa de custo

“Free tier” não significa que todos os serviços de rede sejam sempre gratuitos. Code Engine, VPC, Load Balancer, tráfego e armazenamento devem ser conferidos na conta e na região antes da criação.

Topologia de menor custo

Para experimentar a API, o caminho mais simples é publicar um container no Code Engine e manter banco e serviços de mídia fora da IBM Cloud.

Saídas controladas do container

05 · Imagens e IAAPI → Cloudinary e Google Gemini somente por HTTPS.
06 · LogsAPI → Logtail por HTTPS; sem headers ou senhas no payload.

Como a IBM entra no projeto

O runtime hospeda a imagem Docker; o backend continua sendo o mesmo monólito Express já existente.

Caminho inicial

IBM Cloud Code Engine

Executa a imagem do backend sem administrar uma VM ou cluster Kubernetes. A aplicação recebe uma URL HTTPS pública e deve escutar a porta configurada pelo ambiente.

  • Build da imagem no CI.
  • Push para IBM Cloud Container Registry.
  • Deploy do container no Code Engine.
Evolução

IBM Cloud VPC

Quando for necessário controlar sub-redes, ACLs, Security Groups, IPs e Load Balancer, a API pode migrar para VSI ou outro runtime dentro de uma VPC.

  • Sub-rede pública para o Load Balancer.
  • Sub-rede privada para o compute.
  • Saída por public gateway ou arquitetura de egress revisada.

O que “free tier” cobre

Confirmado na página IBM

Conta e produtos gratuitos

  • Conta Pay-As-You-Go sem compromisso inicial, com produtos que possuem camada gratuita.
  • A IBM informa mais de 40 produtos sempre gratuitos no plano Lite.
  • Crédito inicial de USD 200 por 30 dias para experimentar serviços.
  • IBM Cloudant aparece com 1 GB de armazenamento gratuito.
  • Continuous Delivery aparece com cota mensal de jobs.
Verificar antes de criar

Custos que podem aparecer

  • VPC, VSI, Block Storage e Load Balancer podem depender de promoção, região ou cobrança por uso.
  • Code Engine e Container Registry precisam ter quota/preço confirmados para a conta escolhida.
  • Egress, IP público, logs e armazenamento podem consumir crédito.
  • O free tier não substitui alertas de orçamento e limites de gasto.

Antes do go-live

Os bloqueadores do backend continuam existindo, independentemente do provedor escolhido.

Prioridade alta

Segurança da aplicação

  • API key está desativada em api.ts.
  • JWT existe, mas não é emitido no login nem aplicado às rotas.
  • CORS está aberto para qualquer origem.
  • Segredos aparecem no Compose e precisam ser rotacionados.
Prioridade alta

Persistência e logs

  • Upload de usuário grava em disco local, inadequado para instâncias substituíveis.
  • Logger envia headers e bodies completos, podendo capturar credenciais.
  • Não há readiness real para MongoDB nem health check operacional.
  • GenAI não tem rate limit nem limite de prompt/custo.
Prioridade média

Imagem Docker

  • Declarar tsx diretamente nas dependências de build.
  • Fixar a versão do Node entre Docker e CI.
  • Usar npm ci e uma tag imutável no Registry.
Prioridade média

Operação IBM

  • Criar alertas de orçamento e acompanhar consumo do crédito.
  • Definir região e quotas antes do deploy.
  • Testar restart, escala, logs e comportamento quando Mongo estiver indisponível.

Roteiro IBM

Uma sequência segura para começar pequeno e preservar uma evolução para VPC.

Conta e região

Validar elegibilidade, quotas, região, orçamento e produtos gratuitos disponíveis.

Imagem

Build no GitHub Actions, scan, tag imutável e push para o IBM Cloud Container Registry.

Runtime

Publicar no Code Engine com variáveis em secret/configuration e health endpoint.

Escala

Quando necessário, avaliar VPC, Load Balancer, VSI e controles de rede mais completos.

Decisões para fechar a implantação IBM

  1. Começar com Code Engine para validação ou usar VPC desde o primeiro ambiente?
  2. O frontend continuará separado e consumirá a URL pública HTTPS do Code Engine?
  3. MongoDB Atlas será mantido como banco principal?
  4. As imagens de usuários serão migradas para Cloudinary ou IBM Cloud Object Storage?
  5. Qual limite financeiro e alerta de orçamento serão configurados?
